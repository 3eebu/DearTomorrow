# Security and privacy

**No cross-account content or media disclosure was observed in the exercised fictional-account flows.** This is a bounded result. The confirmed privacy defect is a false storage disclosure at the point of adding a photograph in personal cloud Studio. [DT-QA-01](10-MASTER-ISSUE-REGISTER.md#dt-qa-01--cloud-photo-and-workspace-storage-disclosures).

| Control | What was checked | Result and residual risk |
|---|---|---|
| Authentication and session | Verified-email check, server getUser, fixed application origin, OAuth callback code exchange, token filtering and cookie options. | HTTP-only, SameSite=Lax, HTTPS-dependent Secure in source. Generated-link browser confirmations, rejection of unconfirmed login, password reset and fresh password login succeeded. No fresh external OAuth identity proof or extended idle-session expiry drill on the deployed candidate. |
| Ownership and sharing | Separate fictional identities, independent libraries, intentionally shared book, second private book, private photo, revocation and disconnect. | Hosted development isolation held. Existing policies and request flows were not altered. A screenshot, exported file or previously downloaded photo is outside future read authorization. |
| Partner lookup and race handling | ID-only lookup, counters and limits in connections migration, server RPC, concurrent pairing. | Normal pairing and concurrent acceptance exercised. Display names are distinct from permanent codes. Rate limit implementation reviewed; capacity or abuse-resistance load tests were outside this audit. |
| Private Storage and file handling | Privately scoped bucket, permitted formats, file signature/size checks, owner-prefixed object references and authorized read route. | Development bucket private in current hosted metadata. Shared reader could display the granted photo; the private book did not become readable. Residual retention of unused files requires operator verification. |
| Request integrity and caching | Canonical origin and host comparison, authenticated server session, workspace owner checks, no-store private responses, nosniff, DENY framing header. | Defensive review and regression tests. Check real preview origin and error/cache headers again on the intended release SHA. |
| User input and output | Document schema validation, rich text represented as structured data, React text rendering, allowlisted attachment types, generic private error responses. | These are meaningful controls, not a comprehensive security certification. No exploit or destructive testing was performed against external systems. |
| Credentials and logging | Public URL and publishable key segregated from server-only Supabase credentials. Config rejects several invalid hosted configurations. Checked-in audit artifacts contain no private account records or sign-in links. | Do not treat a publishable key as a privileged authorization. Actual retention, access and redaction settings for production provider logs are unverified. |
| Dependencies | Production dependency audit for the lockfile at review time. | Zero advisories reported in all severities. The scan covers its database of known advisories. [Counts](evidence/dependency-review.json). |
| Account closure and recovery | User action requires typed confirmation and current password followed by a server-side deletion/owned-media cleanup sequence. Test-suite cleanup is an administrator action on verified synthetic records. | A supplemental Settings test closed its fictional password account and confirmed removal of the Auth identity. Google-only closure and recovery from partial deletion remain unverified. Do not count fixture cleanup as a passing customer deletion test. |

No operational secret, one-time link, customer media, actual account UUID or complete permanent Dear Tomorrow ID belongs in these documents. The evidence uses synthetic content and restricts hosted output to aggregate checks. The current HTML/JS surface, request handling and known dependencies were reviewed; continuous monitoring, restore, back-office access and provider operational practices remain independent launch gates.
