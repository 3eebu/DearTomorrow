# Production and commercial readiness

**Decision on 2026-11-26: keep the protected preview. Public release is a no-go.** The complete candidate on main is a different revision from the application the custom domain currently serves. Tests against one do not approve the other.

| System | Current evidence | Release decision |
|---|---|---|
| Hosting, domain and deployment protection | Vercel reports a READY Preview, branch staging, commit 8f1dce45366214c6a19f1ed617699d024f13617e. Protection is set to all. Apex and original staging alias challenge anonymous visits; www redirects to apex. | Appropriate protected environment. Main f3aef74 was built and served locally; it was not rolled out in this audit. A public customer cannot review a protected staging link without authorization. |
| Environment and redirect origins | Public Supabase URL/publishable key, server-only service credential, canonical origin; separate Google/Apple provider flags. Hosted guards reject loopback, invalid schemes and private keys in the public slot. Generated-link callbacks and recovery worked against the development service from the local build. | Redact actual values. Verify separate project, canonically matching HTTPS callback, Secure cookies and sign-out/return on the exact release build. |
| Hosted database and private storage | Four expected migration versions verified in hosted development, private bucket, expiry job active, ten-minute cadence, last run succeeded. Hosted isolation tests passed. | Positive evidence for staging infrastructure. Production separation, backup retention and tested restoration need owner sign-off. |
| Email | Templates and callbacks exist. Generated-link verification/recovery succeeded; no fresh receipt in an authorized mailbox. | Real inbox delivery, template links, sender configuration and provider delivery telemetry remain gates. Historical Resend domain verification is not an inbox test. |
| Google / Apple | Google button visible when configured; app integration and account token/redirect logic covered by regressions. Earlier founder-reported Google return login exists. Apple disabled for this environment. | Fresh consent and return on the selected HTTPS build remain unverified; do not enable Apple to complete this audit. |
| Scheduling | Guest opening is device-clock based. The hosted permission test showed a partner receiving a locked response for future content and being able to read once due. No proactive delivery worker found. | Passive scheduled availability is a valid narrower product. Do not advertise sending emails, notifications, guaranteed delivery or flight telemetry. |
| Large uploads and exports | Chunk limits, retry handling and streaming exercised in tests; real limited-size cloud book/photo and local large model exercised. The localhost client explicitly skips fragment transfer. | Require a real authenticated HTTPS gateway trial with interruption, retry and exported re-import before inviting customers with large archives. |
| Monitoring, logging, backups | Application errors and backup/recovery UI exist. No operational alert receipt, datastore/media restore drill or retention evidence was established. | Assign a responder, test a privacy-safe alert and restore synthetic records and files in isolation. |
| Privacy, terms and account lifecycle | Internal architecture docs exist; no public privacy/terms routes found. Guarded owner closure flow exists. OAuth-only account closure remains a question. | Founder/legal review and an accurate customer-facing explanation are required before collecting public customer memories. |
| Payments | No payment SDK integration, checkout, entitlement model, billing webhook, renewals, cancellation or failed-payment workflow found. No transaction run. | A paid release has no implementable purchase path today. Keep payment outside the freeze; a free release still has the gates above. |
| Search and public availability | Root metadata requests no indexing; staging has Vercel protection and preview response headers. | These are intentional for a protected review. Any launch requires a separate, explicit decision. |

The strongest commercial differentiator is a keepsake people can touch and return to. A selective, genuinely private shared library gives the idea credibility. Converting that into trust depends on accurate storage disclosures, a reliable return/recovery path and believable export/restore. Premium animation has little value to someone who cannot tell where a family photo is being kept. No conversion, subscription price, demand or willingness-to-pay estimate was measured.
