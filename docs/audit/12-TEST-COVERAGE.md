### Evidence and rerun instructions

- Use the [route and source manifest](evidence/source-inventory.json), [unit output](evidence/unit-tests.txt), [browser suites](03-FUNCTIONAL-AUDIT.md), [viewport matrices](05-RESPONSIVE-AUDIT.md), [GPU and video evidence](04-ANIMATION-AUDIT.md), [hosted findings](evidence/hosted-tests.md) and [lifecycle checks](evidence/cloud-lifecycle.json). All captured user-created content is fictional.
- For a comparable local run use the pinned main commit, repository lockfile, Node 22 and npm ci. Run npm run lint, npm run typecheck, npm run build and the repository Node test suite. Start the optimized build on an unused loopback port, with the same origin used by account callbacks. Run the GPU route only from the independent development branch.
- The browser evidence scripts beside the JSON use AUDIT_URL, AUDIT_EVIDENCE, AUDIT_PW (Playwright module), AUDIT_EDGE (Edge binary), optional AUDIT_VIDEO and AUDIT_AXE (path to the axe-core browser script). The viewport script takes edge, firefox or webkit as its final argument. Install browser binaries for that Playwright version. Keep machine-specific browser dependencies outside the application.
- Fixture-generation and inspection should use isolated contexts. Use the repository’s designated-target guard and ignored local credentials for hosted tests. These tests create, pair and remove their own fictional identities. An audit rerun must never attach to a personal profile or point at production.
- The CSS selection and media samples are machine-specific. Throttle settings, viewport, build mode and capture overhead are recorded with results. The single load observations are illustrative and cannot substitute for replicated field p75/p95.

### Still unverified

Genuine inbox delivery, release-origin Google consent, large-transfer retry through the actual protected Vercel gateway, physical iOS/Android keyboard and native Safari, assistive technology speech/Braille, long-session heap/thermal behavior, a full backup restore including private media, and recovery from a partially completed account deletion remain open. A cleared cookie is an unauthenticated-session exercise, not an actual access-token expiration. The audit did not perform a credential extraction, penetration test, payment, deployment or production data operation.

No individual keyboard tab order, hover state, rare failure or creative-tool combination outside the cited cases should be counted as passed. The report distinguishes an observed behavior, a code-supported expectation, an operational dependency and an aesthetic assessment.
